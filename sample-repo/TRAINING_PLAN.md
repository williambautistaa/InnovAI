## Level 1 — Orientation (no code yet)

### Lesson 1 — Understand the project like a stakeholder
- Read `README.md` and the customer interviews in `docs/interviews/`.
- Concepts: MVP, user story, feature request — mapped to what you already know from PM life.

### Lesson 2 — Map the anatomy of the repo
- What `backend/`, `frontend/`, `tests/`, `docs/` mean.
- Analogy: backend = kitchen, frontend = dining room, tests = quality inspectors.

## Level 2 — Programming fundamentals (the repo is the textbook)

### Lesson 3 — Python basics
- Read `backend/app/models.py` together: variables, functions, classes.
- Key idea: "models" describe data, like the columns of a spreadsheet.

### Lesson 4 — How an app talks: APIs
- Read `backend/app/main.py`: what endpoints are (the restaurant menu analogy).

### Lesson 5 — JavaScript/React basics
- Peek at `frontend/src/App.jsx`: how the screen you see is built.

## Level 3 — Hands-on with CODA

### Lesson 6 — Run the app
- Launch backend + frontend, see it working in the browser.

### Lesson 7 — Run the tests
- What tests are, why they fail. This repo has an **intentional bug** planted for practice.

### Lesson 8 — Fix the bug with CODA
- Your first real "dev" achievement, with every change explained.

### Lesson 9 — From requirements to feature
- Extract new features from `docs/interviews/2_meeting_with_customer.pdf`
  (PM-style exercise: requirements → user stories → implement one with CODA).

## Level 4 — PM superpowers

### Lesson 10 — Reviewing code changes
- Learn to judge a change (diff) without writing code.

### Lesson 11 — Capstone: mini sprint
- You define a feature as a user story → CODA implements it → you verify it.
